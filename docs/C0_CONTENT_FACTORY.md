# Content Factory C0: Drive-only approval drafts

C0 is private Commander business tooling. It reuses the Academy's Google authentication and server-authoritative exact founder/COMMANDER_IN_CHIEF access. It does not read personal Core context, change M1/M2/M3 gates, purchase services, or invoke image/video generation.

## Storage boundary

New approval drafts, their copy, scene data, feedback, immutable versions, and approval receipts are stored as private JSON files in the existing canonical Google Drive Content Factory / Organic folder. Source images and review MP4s are also private business Drive files. The app reads them transiently for the authorized founder; API responses use `Cache-Control: private, no-store`. No draft downloads, public media copies, or local export bundles are produced by C0.

MongoDB `enterprisestates` contains only a `C0_DRIVE_DRAFT_POINTER` with owner/item/file IDs, hashes, version, status, timestamps and operation lock. It contains no new package body, feedback text, thumbnail, script, or version history. Existing Workspace OAuth tokens remain encrypted in their existing connection collection. Existing legacy drafts are readable, never automatically migrated or deleted. A Drive outage leaves historical/final campaigns readable with a warning, but no new draft is written elsewhere. Editing/holding/rejecting a legacy record creates a new Drive record and supersedes its old publishing authorization without changing its historical bytes.

The Drive store verifies the exact business Google account, `drive.file`, the configured private folder, file ownership/permissions, MIME, content digest, package hash, and record identity. Every write uploads a new immutable Drive blob, verifies it, then commits its pointer with a compare-and-swap lease. It fails closed rather than saving content in Mongo or the filesystem. A failed/uncertain upload can leave an unreferenced file in Drive; it is not automatically deleted. A crashed lease is not stolen automatically and requires inspection. A successful pointer change is the authority for the current draft.

Limits: 4 MiB per JSON record, 100 listed records; C0 maintains at most 20 package versions and 100 feedback entries per item. Source images are at most 25 MiB; review videos 256 MiB. Slides conversion accepts PNG/JPEG, at most 40 MiB per upload; WebP remains selectable for manual video production but is explicitly labeled as unsupported by the Slides assembler. Shared/public or other-account media is rejected. These are implementation limits, not verified Google account quotas.

## Image-first review

1. Prepare or edit the copy in Drive. New preparation removes old synthetic SVG templates. The actual family-designed logo is the reference, not a newly drawn or hardcoded logo. Its existing Drive file ID is `1hqmbmeslPMilCjwT8cBrdCUkkuEAz2qH`. Original geometry and black/charcoal, silver, deep green/purple with iridescence guide founder review; code cannot certify aesthetic fidelity.
2. Load the exact source-image snapshots, open them in Drive, and explicitly select one image per scene. Approval binds the original logo checksum, image IDs/checksums, scene order, package hash, and full record revision. Changing any scene invalidates image selection. The server rechecks sources before video review and final approval.
3. Assemble in the existing Google tools. No generation or unattended Vids timeline authoring is claimed. Save a review MP4 in private business Drive. Load its exact snapshot before opening and reviewing it. Explicit founder attestations cover readability, audio, transitions, captions, message and visual integrity. These are manual checks, not automated creative or technical QA.
4. Approve one exact finished version. This remains a Drive receipt. C0 does not make a Social draft, public asset, schedule or publish. The private-Drive-to-publishing release adapter is still pending. Slides assembly is an intermediate review artifact, not a finished or approved video.

A loaded file may change after viewing; expected checksums reject such changes at submission. Changing selection or refreshing a logo snapshot clears confirmation. Full record revision checks prevent a stale tab from overriding a hold/rejection even when the package body/hash is unchanged.

## Existing workflow preservation

Historical Mongo C0 drafts and decisions remain available. The former hardcoded three-video materializer no longer recreates them or overrides founder decisions. Existing final C0 publications retain their old exact-approval guard until a new Drive fork supersedes them. Existing public files are not removed as part of this patch.

New ordinary Social campaign drafts and edits also use the same Drive store. Editing a legacy campaign forks rather than overwrites history. Explicit approval locks the exact reviewed revision and materializes only an already-approved campaign in the existing Social collection. Approval and read operations do not activate schedules. If final Mongo approval commits but the Drive receipt response fails, approval remains explicit and final; the response reports receipt-sync pending. An explicit retry verifies the stable campaign ID/hash/version and reconciles the existing Drive receipt without creating another campaign. Ambiguous writes are read-checked before retry; reads do not perform reconciliation. Scheduling/publishing remain separate explicit actions. C0-linked campaigns cannot bypass C0 review through generic Social edit/approve endpoints.

The former local bundle export is blocked because it would create another approval-draft copy. The Slides route now accepts only an exact approved-image package. It embeds private source bytes into an in-memory PowerPoint and converts it directly into native Slides in the private canonical Drive folder; it never makes images public or saves a local presentation draft. Conversion is subject to structural and founder visual review, not automatic creative approval. The obsolete text-only helper is no longer used by the route. The Drive review/edit/hold/image/video-approval path replaces draft persistence; it does not yet finish automated video production or C0 distribution.

## Preparation, voice and schedule limits

Enable with `CONTENT_FACTORY_ENABLED=true`, E0 enabled and the exact `ENTERPRISE_OWNER_USER_ID`. Set an explicit `CONTENT_FACTORY_START_DATE=YYYY-MM-DD` in America/Chicago. Missing start date is reported, not silently reset every day.

The existing catalog is seven days, not thirty. The bounded job checks shortly after boot and every 15 minutes while the process is awake, and prepares up to two days ahead using stable item IDs. It stops at the catalog boundary. No rolling daily long-form production or publication schedule is implemented. Instance sleep can delay preparation. User mentions of 50 or 100 images were exploratory, not an approved batch quota.

`TOI_VOICE_V1` and lineage voices remain rule checks, not certification of authenticity. New feedback is stored in Drive, merged with preserved legacy rules, and exact phrase corrections are applied to future prepared packages. Positive preservation notes are not rejection rules. Manual edits/feedback invalidate approval. No private biography or curriculum is rewritten by this storage change.

## Google production gaps and cost

The app reuses the existing business Workspace connection for `umightcouldb1@toisouljahacademy.com`. Existing OAuth scopes are `openid`, `email`, `profile`, `drive.file`, and `presentations`. No scope expansion is included. `drive.file` only covers files created/opened for this app. Live access to the older logo/source pack must be verified before release; another signed-in Google tool's access does not prove this app has access.

`googleProduction.js` remains an unused text-only Slides helper. `approvedSlides.js` uses the documented Drive PowerPoint-to-Slides conversion route because the native Slides image-insertion API requires public image URLs. PptxGenJS is a free pinned code dependency, not a subscription or new production service. Source bytes and generated PowerPoint exist only in request memory; the first persisted presentation is native Slides in private Drive. Original-logo and selected-image hashes are revalidated, the requested aspect ratio and scene sequence are preserved, and notes hold exact narration. A Drive-persisted operation ID is recorded before conversion; retries only look up and verify that operation, never blindly repeat an uncertain upload. A confirmed pre-upload failure can be retried explicitly after its prerequisite is fixed; uncertain outcomes remain lookup-only. The Vids download helper starts an export operation but does not poll it and persist a finished review file. No supported Vids timeline authoring API has been verified here. Interactive Vids capability, generation entitlement, quota and final export must be verified in the existing business account. ChatGPT/Gemini/Workspace subscriptions do not establish paid API entitlement or price. No additional paid service, API generation, subscription, or spend is invoked by this patch.

Next implementation steps: verify existing app-scoped Drive sources and real conversion fidelity; verify the supported Google editor/export path; implement completed export polling/private Drive save; implement an explicit release adapter for already-approved media; then build the rolling daily long-form plan and evidence-based publication schedule. Do not infer marketing approval from a technically successful historical cut or an unrelated birthday-video template.

## Verification and release

`npm run c0:test` covers the real disposable Mongo + mocked Google integration, storage-only pointer writes, immutable Drive files, exact state/hash checks, failed uploads, owner isolation, private media, image-before-video, legacy supersession, generic Social boundaries and no automatic publishing. It never contacts a production account. The fixture accepts Mongo `--nounixsocket` for restricted local runtimes. `npm run c0:browser` covers the founder UI with real HTTP/Chromium at mobile and desktop widths. The production client build and Social regression harness are required as well.

No production deployment, live draft creation, data migration, permission grant, or deletion is authorized by passing tests. Review this patch and verify live app-scoped Drive prerequisites first. Do not deploy a partial configuration that removes the founder's working path. Do not roll back to Mongo draft persistence after Drive-only use; retain the Drive records and inspect any failed pointer/lease operation rather than copying drafts elsewhere.
